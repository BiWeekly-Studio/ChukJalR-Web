# 축잘알 · Matchday 디자인 시스템 v1

경기를 먼저 보여주고, 예측 선택과 결과를 분명하게 전달한다. 화면마다 새 색과 장식을 추가하지 않고 아래 기준을 확장한다.

## 실행

```sh
npm run design:tokens
npm run dev -- --host 127.0.0.1 --port 4190
```

- 앱 미리보기: `/design/preview.html` — 실제 앱 컴포넌트, 320/390/430px 비교
- 시스템 갤러리: `/design/system.html` — 색·타입·간격·버튼·경기 상태
- 브랜드 갤러리: `/design/brand.html` — 기존 워드로고의 색상 비교·아이콘과 다운로드
- 위 세 페이지는 개발 전용이다. 기본 Vite 배포 엔트리에 포함되지 않는다. 앱 미리보기에서 로그인·시작 안내 화면도 선택할 수 있다.
- 예시 계정·예시 경기만 사용한다. 인증과 모든 데이터 메서드를 mock으로 바꾸며 실제 예측·채팅·구매·결과 확인을 전송하지 않는다. 미리보기 전용 포트를 사용한다.

## 공통 원본

`tokens.json`이 색, 간격, 모서리, 글자 크기, 모션의 원본이다. `npm run design:tokens`로 웹 `src/design/tokens.css`와 iOS `ios/Sources/DesignTokens.swift`를 생성한다. 생성 파일은 직접 수정하지 않는다. iOS는 이번에 공통 색상만 연결하며 네이티브 레이아웃은 별도 구현이다.

## 컴포넌트와 상태

- `MatchCard`는 `featured` 속성으로 같은 동작을 밝은 카드 / 네이비 카드에 제공한다.
- 홈 승·무승부·원정 승은 같은 너비의 세 칸이다. 팀 이름은 대진에, 선택 의미는 버튼의 접근성 이름에 제공한다.
- 선택 전 → 선택 + 확신도 → 예측함 순서. `aria-pressed`는 현재 선택 한 개만 표현한다. 실제 결과는 별도 ‘결과’ 문구로 표시한다.
- 마감·오픈 전 버튼은 `disabled`. 종료 후 적중·실패, 실제 스코어, 지수 변동과 획득 포인트를 나누어 표시한다.
- 참여자 0명 또는 집계 미수신은 가짜 여론 비율을 채우지 않는다. 비율 막대도 숨긴다.
- 주목할 경기는 예측 가능한 내 팀 경기 → 예측 가능한 경기 → 오늘 경기 → 예정 경기 순서. 인기 순위나 추천 지표를 지어내지 않는다.
- 오늘 예측 수와 남은 예측 수는 다르다. 남은 수는 아직 열려 있고 예측하지 않은 경기만 센다.
- 메이저 8개와 기타 대회 그룹을 유지한다. 탭과 전체 대회 선택은 같은 선택 상태를 쓴다.

## 화면 확장 규칙

1. 새 색은 먼저 의미를 정한다. 특별한 의미가 없으면 기존 색을 쓴다.
2. 한 화면의 강조는 주목할 경기와 핵심 동작에 집중한다. 모든 카드를 어둡거나 화려하게 만들지 않는다.
3. 긴 팀명은 줄바꿈한다. 작은 화면에서 경기 상대를 생략하지 않는다.
4. 오류·없음·불러오는 중을 구분한다. 실제 수치가 없으면 숫자나 성공 문구를 지어내지 않는다.
5. 누를 영역은 주요 동작 44px 이상. 키보드 포커스를 숨기지 않고 선택/결과를 색에만 의존하지 않는다.
6. `prefers-reduced-motion`을 유지한다. 동작 확인을 장식 애니메이션에 의존하지 않는다.
7. 변경 후 320/390/430px, 긴 팀명, 참여자 없음, 오픈 전, 마감, 적중·실패를 확인한다.

## 이번 적용 범위

웹·앱인토스: 홈 정보 구조, 대회 탐색, 주목할 경기, 공통 경기 카드, 점수 요약, 주요 버튼·하단 탐색, 경기 상세·채팅, 랭킹, 내 기록, 로그인·시작 안내, 지원·약관 페이지에 같은 디자인을 적용했다. 랭킹은 실제 전체 순위와 내 순위를 표시하며, 내 기록은 기록·응원/도전·설정으로 나누었다. 화면별 공통 규칙은 `src/design/screens.css`에서 관리한다.

기존 축잘알 워드로고의 형태와 단일 ‘축’ 아이콘을 유지하고 네이비·흰색·라임 팔레트를 적용했다. 사용 규칙은 [BRAND.md](./BRAND.md)에 정리했다. iOS는 공통 색상 토큰·브랜드·리그 편집을 연결했으며, 이번 앱인토스 화면 개편을 네이티브 전체 레이아웃에 적용한 것은 아니다.

리그 순서 편집: 웹 리그 탭 옆과 iOS 대회 선택 위의 `순서` 버튼에서 메이저·기타 그룹별로 이동한다. 저장 전에는 초안이며, 취소하면 기존 순서를 유지한다. 기본 순서 복원은 전체 그룹을 대상으로 한다. 저장 성공 후에만 홈에 반영하고 현재 보고 있던 대회는 유지한다. 새 대회는 빠짐없이 목록 뒤에 추가된다.

웹·iOS는 본인의 `profiles.league_order`만 갱신하며 즐겨찾는 팀·온보딩·알림 설정을 수정하지 않는다. 실제 서버 저장은 연결했고, 로컬 검수에서는 격리된 저장 모형을 사용했다. 디자인 미리보기의 순서는 별도 브라우저 저장소에 보관한다.
