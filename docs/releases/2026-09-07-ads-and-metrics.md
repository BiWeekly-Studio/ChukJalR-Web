## 빌드

```sh
# 콘솔 QR 테스트용. 운영 광고 ID를 설정했더라도 테스트 ID만 포함한다.
npm run build:toss:ads:test

# 운영 ID 발급 후 .env.production.local에 아래 키를 추가한다.
# VITE_TOSS_BANNER_AD_GROUP_ID=콘솔에서_발급된_운영_ID
npm run build:toss:ads:live
```

운영 빌드는 ID가 없거나 테스트 ID이면 즉시 실패한다. 결과는 각각 `artifacts/chukjalr-ads-test.ait`, `artifacts/chukjalr-ads-live.ait`에 저장한다. 기본 `build:toss`에서는 `VITE_TOSS_ADS_MODE`를 명시하지 않으면 광고가 꺼진다. 자체 웹 빌드는 광고 모드와 무관하게 광고를 요청하지 않는다.

## 검증과 남은 확인

- 기존 및 배너 테스트 23개, 분석 이벤트 테스트 3개 통과. 실제 소스를 실행해 SDK 중복 초기화, 미지원, 비동기 취소, no-fill, 렌더링 예외, 슬롯 정리, 지표 전송 실패를 확인했다.
- TypeScript 및 토스 QA 번들 빌드 성공, 별도 웹 빌드 성공.
- QA 번들에는 테스트 ID가 포함되고 사용자 예측 이벤트는 포함되지 않음을 확인했다. 웹 번들에서는 광고 ID 및 사용자 예측 이벤트가 제거됨을 확인했다.
- 운영 ID 누락 시 빌드 중단 확인.
- 휴대전화: 최신 광고 QA 버전의 테스트 QR로 접속해 로그인/안내 후 첫 경기 카드 다음 배너를 확인한다. 경기 상세·순위표 이동 시 광고가 제거되는지도 확인한다.
- 운영 ID 발급 및 휴대전화 QA 완료 후 운영 번들을 업로드하고 검토·출시 절차를 진행한다. 실제 운영 광고로 테스트 트래픽을 만들지 않는다.

## 수익 구조 확인 (2026-09-07)

- 공식 문서상 송출 운영비는 광고 매출의 약 30% 수준이다. 이후 광고 수익에 앱인토스 수수료 15%를 적용하는 구조지만 현재 15% 수수료는 면제 프로모션 중이다. 송출 운영비까지 면제되는 것은 아니다.
- 정산은 사업자 단위로 합산하며, 필요한 등록·승인 절차를 거쳐 익월 말일에 지급한다. 정산 받을 수입 5,000원 이하는 다음 달로 이월한다.
- 공식 정산 문서 내부에 역발행 승인 마감이 10영업일/4영업일로 혼재하므로 실제 승인 요청 안내의 마감을 확인해야 한다.
- 예상 광고 수익 = 실제 노출 수 × eCPM ÷ 1,000. 콘솔 예상 수익과 최종 정산금은 구분한다. 이미 차감이 반영된 콘솔 수익에 운영비를 중복 공제하지 않는다.
- 예시 가정: eCPM 1,000원, 사용자당 일 실제 노출 2회, 30일. 일 이용자 1,000명 → 월 예상 6만 원, 5,000명 → 30만 원, 10,000명 → 60만 원. 실제 단가나 수익을 보장하는 예측이 아니다.
- 후속 제안: 초반 배너 + 선택형 보상 광고(예: 내 예측 성향 상세 리포트). 보상형은 아직 구현하지 않았다. 광고 시청으로 예측 점수나 순위를 올리는 구조는 사용하지 않는다.
